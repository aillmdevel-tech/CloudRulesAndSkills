# Автопроверки игры

Оба инструмента — Python Playwright, Chrome (`headless=False`, `--use-angle=metal`), игру берут из прод-сборки `dist/` (`vite preview`, порт 4189); сервер поднимают и гасят сами. Управление игрой — через `window.__game` (есть и в проде), общий код в `tools/lib/` (`harness.py` — сборка, сервер, сессия браузера; `spy.js` — перехват Bridge).

## Смоук-тест — `npm run smoke`
Отвечает на вопрос «работает ли». Визуал не оценивает (это делает модель по скриншотам).
- Флаги: `-- --dev` (vite dev вместо prod), `-- --no-build` (не пересобирать), `-- --url <адрес>` (уже запущенная игра).
- Сценарий ≈ 1 мин: загрузка (Bridge init, `game_ready`, консоль чистая) → лобби (стоит на земле, W двигает) → тренажёр (стыковка, растёт XP) → Stage 1 (хват, высота растёт, grip тратится) → «YOU FELL» → возврат в лобби → звук (AudioContext, музыка и шаги загружены) → консоль чистая.
- Вывод: строка `✓/✗ шаг: причина` на каждый шаг, число ошибок консоли, итог `PASS` / `FAIL (n/m)`; код выхода 0/1. Скриншоты — `tools/out/smoke/` (в git не попадают).
- Запускать после каждого плана изменений (Sonnet), до «готово».

## Модератор — `npm run moderate -- --platform playgama|crazygames|all`
Прогоняет правила площадки по прод-сборке и **в реальном времени перезаписывает `docs/moderation/REPORT.md`** (по площадкам: ✓ / ✗ / 👀 вручную / ⏳ ещё не проверено; в конце — замечания «номер правила → файл для исправления» и вердикт «можно / нельзя отправлять»). Код выхода 0 = можно, 1 = нельзя. Флаги: `--no-build`, `--dev`.
- Правила: `tools/moderator/rules/<площадка>.json` (id, title, type `auto|manual`, check — имя функции из `checks.py`, needs — какие пробы нужны, fix — файлы, note). Чтобы добавить площадку (например Яндекс) — положить `yandex.json` в том же формате; новые проверки — функцией в `checks.py` с декоратором `@check`.
- Источники: Playgama — номера из официальных Game Requirements (`get_game_checklist`, wiki.playgama.com); CrazyGames — docs.crazygames.com/requirements (у них нет нумерации: id = «раздел.пункт»). Номера не выдумываются; при смене официальных правил обновить JSON.
- Пробы (`probes.py`): `static` (размер/файлы/имена/index.html, grep исходников, версия Bridge), `boot` (старт, game_ready, внешние запросы, звук до/после жеста, тексты/emoji/mute), `ads` (эмуляция рекламы: interstitial, rewarded ok / закрыт без награды / ошибка — пауза, звук, награда), `pause` (audio/pause платформы, скрытая вкладка), `persist` (сохранение, перезагрузка), `sizes` (12 размеров окна, скриншоты в `tools/out/moderator/sizes/`).
- Эмуляция рекламы: `tools/lib/spy.js` оборачивает `window.bridge` в Proxy, записывает вызовы и по флагу `__spy.emulate` сам отвечает на `showInterstitial/showRewarded` событиями `opened → rewarded → closed` через внутренний `_platformBridge`; mock-платформа Bridge без этого рекламы не поддерживает.
- Что автопроверка не может: подлинность платформенной рекламы, Safari/Firefox/мобильные, контент-ревью, ощущение игры. Такие правила получают статус «вручную» с подсказкой.
- Для CrazyGames по умолчанию режим Full Launch: пока нет адаптера CrazyGames SDK (`gameplayStart`, Data module, реклама), эти правила будут ✗.

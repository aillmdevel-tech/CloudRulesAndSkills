# Процесс разработки игры (единый алгоритм)

Машинная версия — скилл `game-project-workflow`. Этот файл — единственное описание алгоритма для человека; другие файлы на него ссылаются.

## Правила, общие для всех шагов
- **Один чат на проект.** Вся разработка, Blender и проверки — в нём. Сабагенты только на объёмную рутину (нарезка видео, поиск по коду, смоук), возвращают короткий итог. Сессии и новые чаты агент сам не открывает. Новый чат — когда Alex пишет «упакуй контекст» (→ `PROJECT_STATE.md` + memory-bank → «продолжи работу») или начинает другой проект.
- **Модель и уровень мышления выбирает Alex.** Агент их не переключает; если считает, что задаче нужен другой уровень, говорит одной строкой.
- **Цикл каждого пакета правок:** код → `tsc` + сборка → смоук и тесты механик (`game-autotest`) → снимки «референс | игра» (`game-visual-comparison`) → правка расхождений → коммит → `PROJECT_STATE.md` и memory-bank.
- **Геймдизайн-фильтр.** Каждое решение сверяется с `DESIGN/CONSTITUTION.md` (формула 5 шагов, первая минута, 3 горизонта целей, 20 запретов). Нарушение — вопрос Alex, а не тихая правка.
- **Bug shield.** Перед пакетом правок — заголовки `LESSONS/<тема>.md` по затронутой теме. Нетривиальный баг исправлен → урок в `LESSONS/` (симптом, причина, фикс, правило, проверка).
- **Готовые механики.** Механика принята Alex или далась тяжело → запись в `MECHANICS/` с кодом и тестом; новая игра сначала ищет механики там.
- **Ничего от себя.** Объём = ТЗ + ответы Alex. Идеи сверху — только как вопрос.

## Общие библиотеки
`DESIGN/` (конституция, фильтр идеи, скелет, первая минута, воронка, Roblox) · `DesignLibrary/` (разборы игр, паттерны, хуки, механики по жанрам) · `LESSONS/` (bug shield) · `MECHANICS/` (готовые механики с тестами) · `StyleLibrary/` (стиль) · `UIFX/` (UI-анимации и звуки) · `WebAIGames/PromoLibrary` (промо).

## Шаги
-1. **Идея** (если игры ещё нет или идея не проверена). Разведка `game-idea-scout` или идея Alex → фильтр 15 вопросов (`DESIGN/IDEA_FILTER.md`) → `docs/IDEA.md`. Обязательные 1–3 = 0 → стоп, переформулировать. Похожие игры и паттерны — из `DesignLibrary` (`game-design-library`).
0. **Стиль.** Присланные Steam-игры → `StyleLibrary`. Иначе используется существующая библиотека.
1. **Материалы.** Alex кладёт в `input/` проекта видео Roblox-оригинала, расшифровку и полное ТЗ (весь цикл игры).
2. **Разбор, без кода.** Видео → кадры и листы (`game-reference-analysis`), оригинал изучается в вебе. Итог — `docs/spec/` (mechanics, visual, ui, vfx, animation, camera, audio), каждый пункт помечен [видно] / [из ТЗ] / [пробел]. Плюс **скелет** `docs/GAME_SKELETON.md` — 17 колонок пути игрока (`DESIGN/SKELETON.md`): пустая колонка = [пробел]; паттерны для дыр — из `DesignLibrary`.
3. **Вопросы только по пробелам.** Раунды до 5 вопросов, только по [пробел] и противоречиям ТЗ/видео, к каждому вариант агента. «Не знаю» = принят вариант агента. Ответы сразу в `docs/DECISIONS.md` и в скелет. **Код не начинается, пока все пробелы не закрыты.**
4. **Стиль и бюджет.** Доска 3–6 Steam-игр под проект (`game-art-first`) → Alex утверждает одну. В `docs/ART_SPEC.md`: палитра, свет, пост, коридор яркости/насыщенности, главный приём. В `docs/GAME_DESIGN.md`: бюджет (вес билда, FPS на слабом ноуте). Стек — из `THREEJS_STACK.md`, если ТЗ не задаёт другой.
5. **Готовое.** После утверждения стиля, до плана, один проход (`game-art-first` §3): бесплатные ассеты CC0 в утверждённом стиле (Poly Haven, Poly Pizza, Kenney, Quaternius; поиск через Blender MCP), открытые проекты на GitHub с похожими механиками, нужные библиотеки. Итог — `docs/REFERENCES.md`: ссылка, лицензия, что берём, оценка 1–5. Скачивание — после «ок» Alex.
6. **План.** Как агент видит игру, что берётся готовым из `REFERENCES.md` и `MECHANICS/`, а что делается в Blender, состав MVP, этапы до конца → `docs/plans/…-master.md` + строка в `CURRENT.md`. Работа начинается по «приступай».
7. **MVP-сцена** = первые 2–3 минуты игры из ТЗ, маленькая, но полностью законченная. Первая минута — маленькая версия всей игры: фантазия за 3 с, первое действие ≤ 10 с, мир меняется ≤ 30 с, следующая цель видна ≤ 60 с (`DESIGN/CONSTITUTION.md` §3). События воронки (`templates/funnel/funnel.ts`) ставятся сразу. Геймфил, механики, элементы, VFX и персонаж — с Roblox-оригинала; стиль — с утверждённой Steam-игры.
   - Состав: одна стартовая зона (Blender, утверждённый стиль: земля, границы, 5–10 видов декора, небо, туман, свет); персонаж или машина с управлением, камерой и анимациями как в оригинале; 3–5 видов интерактивных объектов с физикой и коллизиями; один полный короткий цикл из ТЗ (действие → результат → награда); VFX, постобработка, звуки и музыка без авторских прав; минимальный HUD.
   - Не входит: другие локации, прогрессия, магазин, сохранения, SDK площадок, мобильное управление (если ТЗ не требует сразу).
   - Три проверки Alex, между ними агент работает сам:
     - **A. Кадр стиля** — угол зоны в Blender и снимок из движка рядом со Steam-референсом.
     - **B. Геймфил и первая минута** — управление, камера и ядро механики на этой зоне, сравнение с видео оригинала; параметры в одном конфиге. Плюс `npm run first-minute` и холодный взгляд сабагента по кадрам (`DESIGN/FIRST_MINUTE.md`), тесты механик `npm run mechanics`.
     - **C. Готовая сцена** — объекты, цикл, VFX, звук, HUD, бюджет; ссылка на игру и листы сравнения.
8. **Расширение до конца.** После «MVP принят»: этапы мастер-плана (локации, контент, экономика, UI, площадки), каждый пакет — тем же циклом. Правки Alex (текст или видео с голосом) разбираются как в шаге 2. Перед отправкой — модератор (`game-autotest`) и промо-набор (`game-promo-kit`: ролики, превью, скриншоты, обложки по правилам площадки и на всех языках).
9. **После запуска — воронка.** Через 3–7 дней: цифры кабинета площадки + наш дневник событий → самый большой обрыв → одна правка геймплея → новая сборка → новая воронка (`DESIGN/FUNNEL.md`, `retro` режим «воронка»). Итог — карточка `DesignLibrary/games/our-<slug>.md`. Игра держит игроков → вкладываемся (контент, перенос на Roblox: `DESIGN/ROBLOX.md`); не держит → урок в базу, следующая идея.

## Быстрая игра (портфельный режим)
Хиты редки, выигрывает число проверенных попыток. Режим по фразе «быстрая игра»: шаги −1 → 2 (скелет) → 7 в сокращённом виде, цель — опубликовать за 2–5 дней.
- Объём: одна зона, одно главное действие, один цикл, 3 горизонта целей (долгая цель может быть показана, но не сделана), воронка, SDK площадки.
- Стиль: готовый из StyleLibrary без доски (Alex подтверждает одной фразой), ассеты CC0 + Blender по минимуму.
- Проверки: A и B объединяются в одну (кадр стиля + первая минута), C — смоук, модератор, промо-минимум (обложка, 1 превью).
- Рост: только для игры с лучшей воронкой.

## Что писать агенту
- Идеи: «найди идеи для игры» / «прогони идею через фильтр: …».
- Старт: «Новый Roblox-like проект. Материалы в input/. Стиль: [Steam-ссылки / из StyleLibrary].» Быстро: «быстрая игра: <идея>».
- База: «разбери записи в inbox» (как записывать — `DesignLibrary/RECORDING.md`).
- После запуска: «разбери воронку».
- После ответов на вопросы и доски: «приступай».
- Правки: текст или видео → «разбери правки и делай».
- Расширение: «MVP принят, работай по плану до конца».
- Чат тяжёлый: «упакуй контекст» → новый чат в папке проекта → «продолжи работу».
- Готовый план из другого места: «выполни план» (агент открывает `docs/plans/CURRENT.md`, идёт по шагам, отмечает готовые, завершает проверками).

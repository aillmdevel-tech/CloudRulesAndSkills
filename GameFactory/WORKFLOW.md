# Процесс разработки игры

Полная машинная версия — скилл `game-project-workflow`. Здесь — коротко для человека.

1. **Материалы** — ТЗ (можно голосом), видео геймплея, скриншоты, выгрузки LevelCopier, ассеты.
2. **Изучение** — Claude разбирает видео покадрово (FFmpeg, таймкоды), скриншоты, ассеты; выбирает стек по ТЗ.
3. **Уточнение** — только вопросы, меняющие механику/архитектуру/объём; до ~5 за раз, с рекомендуемым ответом.
4. **Согласование** — понимание игры, цикл, управление, камера, уровни, UI, стек, архитектура, первый срез, что отложено. Без твоего «ок» масштабной реализации нет.
5. **Вертикальный срез** — минимальный набор законченных связанных механик. Строго в рамках согласованного.
6. **Тестирование** — tsc, сборка, запуск, консоль, управление, логика, коллизии, камера, UI, скриншоты против референса.
7. **Итерации** — твой плейтест → задачи → исправления → повторная проверка.

Документы проекта (`docs/`): `PROJECT_STATE.md` (на старте читается актуальный блок), `DECISIONS.md`, `TASKS.md`,
`GAME_DESIGN.md`, `ARCHITECTURE.md`, анализ референсов (`REFERENCE_ANALYSIS`, `VIDEO_STORYBOARD`,
`GAMEPLAY_BREAKDOWN`, `ART_REFERENCE`, `ART_SPEC`) и `ASSET_MANIFEST.md` для импортов.

| Готовый репозиторий | его стек |

## План для Sonnet

Запрос «составь план для Sonnet» или «составь план по опусплан» запускает изучение нужных файлов и подготовку плана без правок кода. Запиши `docs/plans/YYYY-MM-DD-<коротко>.md` и одну строку со ссылкой на него в `docs/plans/CURRENT.md`.

Включи цель, критерий готовности, стек, ключевые файлы и границы работ. На каждый шаг дай чекбокс, точку изменения в коде, риски и способ проверки. План должен быть понятен исполнителю в новом чате. В ответе дай путь и команду «Выполни план».

На «выполни план» открой `docs/plans/CURRENT.md`, затем сам план. Выполняй шаги по порядку и отмечай готовые. Если шаг расходится с кодом, уточни его. Заверши проверками из плана и обнови `PROJECT_STATE.md`.

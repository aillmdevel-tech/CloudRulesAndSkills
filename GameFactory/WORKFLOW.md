# Процесс разработки игры

Полная машинная версия — скилл `game-project-workflow`. Здесь — коротко для человека.

1. **Материалы** — ТЗ (кратко: механики, требования), название оригинальной игры (чаще Roblox), видео, скриншоты, выгрузки LevelCopier, ассеты.
2. **Изучение** — скрипты разбирают видео покадрово (FFmpeg), скриншоты — стиль, пропорции, UI; оригинал изучается в вебе; выбирается стек.
3. **Поиск готового** — ассеты (CC0), GitHub-проекты, игры в вебе/Steam как визуальный референс → `docs/REFERENCES.md`.
4. **Опрос (grilling, включается сам)** — до ~5 вопросов за раунд, у каждого мой вариант ответа; «да» принимает его.
5. **Согласование** — как я вижу игру, стиль и 3–4 варианта адаптации референса, стек, поэтапный план от начала до конца. Без твоего «ок» работы нет.
6. **Старт («приступай»)** — в проекте пишутся GAME_DESIGN, ARCHITECTURE, REFERENCES, мастер-план `docs/plans/…-master.md` (шаги, критерии, где что лежит, какая модель на какой шаг) + строка в `CURRENT.md`.
7. **АРТ сначала** (`game-art-first`) — стиль, карта, локация, объекты в Blender (MCP) → GLB → сверка скриншотов с референсом → твоё одобрение картинки.
8. **MVP-сцена** — логика на утверждённой сцене: движение, камера, цикл, коллизии, минимальный UI. Строго в согласованном объёме.
9. **Тестирование** — tsc, сборка, смоук, консоль, управление, логика, коллизии, камера, UI, скриншоты против референса.
10. **Масштабирование и итерации** — новые UI, локации, контент, полировка; твой плейтест → задачи → исправления → проверка.

Кто делает: дизайн, механики, локации, модели, камера, визуал — ведущий (Opus high); простые проверки, скрипты, экспорты, смоук — Sonnet/Opus medium по письменному ТЗ с командой проверки (`game-art-first/references/model-routing.md`).

Документы проекта (`docs/`): `PROJECT_STATE.md` (на старте читается актуальный блок), `DECISIONS.md`, `TASKS.md`,
`GAME_DESIGN.md`, `ARCHITECTURE.md`, `REFERENCES.md`, анализ референсов (`REFERENCE_ANALYSIS`, `VIDEO_STORYBOARD`,
`GAMEPLAY_BREAKDOWN`, `ART_REFERENCE`, `ART_SPEC`), `spec/`, `plans/` и `ASSET_MANIFEST.md` для импортов.

## План для Sonnet

Запрос «составь план для Sonnet» или «составь план по опусплан» запускает изучение нужных файлов и подготовку плана без правок кода. Запиши `docs/plans/YYYY-MM-DD-<коротко>.md` и одну строку со ссылкой на него в `docs/plans/CURRENT.md`.

Включи цель, критерий готовности, стек, ключевые файлы и границы работ. На каждый шаг дай чекбокс, точку изменения в коде, риски и способ проверки. План должен быть понятен исполнителю в новом чате. В ответе дай путь и команду «Выполни план».

На «выполни план» открой `docs/plans/CURRENT.md`, затем сам план. Выполняй шаги по порядку и отмечай готовые. Если шаг расходится с кодом, уточни его. Заверши проверками из плана и обнови `PROJECT_STATE.md`.

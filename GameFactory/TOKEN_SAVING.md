# Экономия токенов и лимитов (правила для всех проектов)

Агент применяет сам; Alex только подтверждает то, что трогает его настройки.
1. **Один тип работы — одна сессия**; параллельно в одной папке — только если задачи не пересекаются. Каждая сессия заново читает проект.
2. **Тяжёлое чтение — субагенту**: видео/кадры, поиск по всему коду, большие логи, инвентаризация ассетов. В основной чат — только вывод. Субагенту — правила формата ответа (кратко, по-русски).
3. **Фоновые команды и узкий вывод**: сборки/смоук/модератор — `run_in_background`, читать итог (tail, grep, вердикт), не полный лог/отчёт.
4. **Чтение — точечное** (offset/limit, grep), правки — Edit, не перезапись файла. Не перечитывать проект ради мелочи.
5. **Лишние MCP-серверы** (Blender, Chrome, Playgama и др.) добавляют описания инструментов в контекст каждой сессии. Перед работой, где они не нужны, скажи Alex одной строкой «отключи MCP X (/mcp или Коннекторы)»; сам настройки не менять.
6. **PROJECT_STATE.md / CLAUDE.md проекта — короткие**: их читает каждый новый чат. Без длинных списков ссылок и повторов того, что есть в docs/. Сжимать при handoff, не теряя фактов (пути, команды, решения Alex).
7. **Контекст**: ≥150k или 2 сжатия → handoff и новый чат (хук context_guard). Длинный чат дорог.
8. **Диагностика расхода**: Alex говорит «куда ушли токены» → скилл `explain-usage`.
9. Качество не режем: проверки (tsc, build, smoke, браузер) не пропускаются ради экономии.

# Фильтр новой идеи: 15 вопросов

Запускается до разбора ТЗ (шаг «Идея» в `WORKFLOW.md`) и для каждой идеи из разведки (`game-idea-scout`). Результат — `docs/IDEA.md` проекта (шаблон `templates/docs/IDEA.md`).

## Как отвечать
Каждый вопрос: **2** — да, видно в материале (кадр, ТЗ, оригинал); **1** — частично или только на бумаге; **0** — нет. Рядом одна строка доказательства (таймкод, ссылка, пункт ТЗ). Отвечать честно: идея Alex тоже проходит фильтр, агент не подыгрывает.

## Обязательные (если хоть один = 0, остальные двенадцать идею не спасут)
1. Понятно ли обещание игры с одного взгляда? (обложка/первый кадр → фантазия в одну фразу)
2. Есть ли простое главное действие? (один ввод, приятное само по себе, без меню)
3. Даёт ли первое действие видимый результат? (мир меняется, не только цифра)

## Почему не надоедает
4. Видна ли желанная награда заранее?
5. Возникают ли понятные решения (куда потратить, что открыть первым)?
6. Создаёт ли действие следующую цель?
7. Растёт ли что-то личное (своё место, коллекция, персонаж)?
8. Есть ли у объекта несколько ролей?
9. Видно ли будущее и больший масштаб?

## Почему возвращаются
10. Нарушается ли иногда рутина (события, редкие гости, случайности)?
11. Создают ли игроки истории друг другу (в вебе — рекорды, сравнение, шаринг)?
12. Превращается ли потеря в действие?
13. Ждёт ли игрока результат после выхода?
14. Меняется ли мир между сессиями?
15. Доказывается ли главное маленьким MVP (2–5 дней)?

## Вердикт
- Любой из 1–3 = 0 → **стоп**: переформулировать фантазию или действие, либо отказаться.
- Сумма 4–15 < 12 из 24 → **слабо**: показать Alex, какие 2–3 вопроса поднять, и как.
- Иначе → **в работу**, слабые пункты становятся [пробел] в скелете.

Также указать: жанр (папки `DesignLibrary/mechanics/`), 2–3 похожие игры из `DesignLibrary/games/` с их онлайном и причиной смерти, если есть.

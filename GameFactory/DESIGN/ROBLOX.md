# Перенос игры на Roblox

Дизайн-слой (конституция, скелет, первая минута, воронка, DesignLibrary) не зависит от движка: он одинаков для веба и Roblox. Меняется код, сборка сцены и монетизация. Конкретные лимиты и API Roblox сверять с create.roblox.com/docs в момент работы — они меняются.

## Что переносится как есть
| Из веб-проекта | В Roblox |
|---|---|
| `docs/IDEA.md`, `GAME_SKELETON.md`, `spec/`, `DECISIONS.md` | те же документы, колонки 14 «Люди» и 16 «Монетизация» переписать под Roblox |
| Модели из Blender | экспорт FBX/glTF → 3D Importer Studio; держать низкую детализацию и малый размер текстур |
| Звуки и музыка (свои/CC0) | загрузить как свои ассеты (проходят модерацию Roblox) |
| UI-дизайн, иконки | пересобрать в ScreenGui (Frame, UIStroke, UICorner, TweenService вместо UIFX) |
| Промо-брифы и PromoLibrary | те же паттерны Roblox-промо; иконка и миниатюры по требованиям Roblox |

## Что пишется заново
- **Код:** TypeScript/Three.js → Luau. Логика делится на сервер (`ServerScriptService`, авторитетная) и клиент (`StarterPlayerScripts`, ввод, камера, эффекты), связь — `RemoteEvent`/`RemoteFunction`. Никакой экономики на клиенте.
- **Физика и персонаж:** встроенные Roblox (Humanoid, R15). Свой контроллер — только если механика требует.
- **Сохранения:** `DataStoreService` (лучше через проверенную обёртку уровня ProfileStore) — сессионная блокировка, ретраи.
- **Монетизация:** Game Passes (навсегда) и Developer Products (расходуемые) через `MarketplaceService`, точки из колонки 16 скелета.
- **Люди:** настоящий мультиплеер — вместо лидерборда-заглушки: совместное, зависть (видно чужое растущее), торговля.

## Инструменты для Claude
- **Rojo** — синхронизация папки с `.luau` файлами в Studio: код живёт в git, Claude правит файлы как обычно.
- **Luau LSP / selene / StyLua** — типы, линт и формат в терминале (аналог `tsc`).
- **Roblox Studio MCP** (официальный сервер Roblox для Studio) — живая работа со сценой, как Blender MCP. Включать только для этой работы.
- Тесты: TestEZ или Jest-Lua для логики (экономика, формулы), плюс запуск в Studio через MCP для смоука.

## Порядок переноса
1. Решение по воронке веб-версии: переносим только игру, которая держит игроков (или идею, сильную именно мультиплеером).
2. Скелет: переписать колонки 14 и 16, добавить серверную модель данных (что хранится, что реплицируется).
3. Новый проект Rojo (`default.project.json`, `src/server`, `src/client`, `src/shared`), шаблон добавим в GameFactory при первой Roblox-игре.
4. MVP-сцена той же первой минутой: проверка первой минуты в Studio (Play Solo + запись экрана → тот же холодный взгляд).
5. Публикация: иконка, миниатюры, описание, возрастной опросник, приватный тест → публичный запуск → воронка в Creator Dashboard.

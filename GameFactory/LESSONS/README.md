# LESSONS: bug shield

Каждый исправленный нетривиальный баг оставляет урок, чтобы он не повторился ни в этой, ни в следующей игре. Пишет агент сам, без просьбы, в конце `diagnosing-bugs` (Phase 6) и после любого фикса, на который ушло больше одной попытки.

## Где

|---|---|
| [threejs.md](threejs.md) | рендер, шейдеры, пост, материалы, память, FPS |
| [physics.md](physics.md) | Rapier, коллизии, персонаж, камера, NaN |

| [platforms.md](platforms.md) | SDK Playgama/CrazyGames, реклама, пауза, модерация |
| [testing.md](testing.md) | смоук, пробы, ложные ✗, тайминги тестов |

## Формат записи (5 строк, новые сверху)
```
### YYYY-MM-DD · Проект · коротко
- Симптом: что видел игрок/тест.
- Причина: корень, не следствие.
- Фикс: что поменяли (файл/функция).
- Правило: как не допустить в любой игре (одна фраза, императив).
- Проверка: тест/проба, которая теперь краснеет на этом баге (или «нет — почему»).
```

## Как читать
- Старт проекта и начало пакета правок: заголовки файлов по затронутой теме (`grep -h '^### \|Правило' LESSONS/<тема>.md`).
- Перед фиксом похожего симптома: `grep -ri '<ключевое слово>' LESSONS/`.
- Правило, повторившееся в 2+ играх, переносится в шаблон (smoke, ADAPT.md, THREEJS_STACK.md) или в автоматическую проверку, а запись помечается «→ в шаблоне».
